# Git y GitHub

## ¿Qué es Git?

Git es un sistema de control de versiones distribuido y de código abierto creado por Linus Torvalds. Su función principal es realizar el seguimiento de los cambios realizados en los archivos de un proyecto, permitiendo gestionar versiones, colaborar con otros desarrolladores y mantener un historial completo de modificaciones.

## ¿Qué es GitHub?

GitHub es una plataforma basada en la nube que utiliza Git como tecnología principal. Permite almacenar repositorios, colaborar con otros usuarios y administrar proyectos mediante herramientas como ramas, commits, Pull Requests e Issues.

## Repositorio

Un repositorio es el espacio donde se almacenan los archivos, carpetas e historial de cambios de un proyecto. Los repositorios pueden ser públicos o privados y permiten la colaboración entre múltiples usuarios.

## Rama (Branch)

Una rama es una versión paralela de un repositorio que permite desarrollar nuevas características, corregir errores o realizar pruebas sin afectar la rama principal. Posteriormente, los cambios pueden integrarse mediante una fusión (Merge).

## Clon (Clone)

Clonar un repositorio consiste en descargar una copia completa del proyecto desde GitHub a un equipo local, incluyendo archivos, carpetas e historial de versiones.

## Fork

Un fork es una copia de un repositorio que se crea en una cuenta diferente de GitHub. Permite experimentar o desarrollar cambios sin afectar el repositorio original.

## Remoto (Remote)

Un repositorio remoto es aquel que se encuentra alojado en una plataforma como GitHub y puede ser compartido entre varios colaboradores.

## Upstream y Downstream

- **Upstream:** Repositorio original del cual se realizó un fork.
- **Downstream:** Repositorio derivado creado a partir de un Fork, el cual puede sincronizar cambios provenientes del repositorio original cuando sea necesario.

## Commit

Un commit representa un conjunto de cambios realizados en un proyecto.

Mediante un commit es posible:

- Agregar archivos.
- Modificar archivos existentes.
- Renombrar archivos.
- Eliminar archivos.
- Registrar un punto específico del historial del proyecto.

## Pull Request

Una Pull Request es una solicitud para fusionar cambios de una rama hacia otra.

Permite:

- Revisar cambios antes de integrarlos.
- Recibir comentarios y sugerencias.
- Aprobar o rechazar modificaciones.
- Mantener un flujo de trabajo colaborativo.

## Fusión (Merge)

La fusión consiste en tomar los cambios realizados en una rama y aplicarlos a otra rama, normalmente hacia la rama principal del proyecto.

## Markdown (.md)

Markdown es un lenguaje de marcado ligero utilizado para formatear documentación y texto de forma sencilla.

Los archivos con extensión `.md` permiten crear títulos, listas, tablas, enlaces e imágenes de manera fácil y legible tanto para humanos como para plataformas como GitHub.

## Propiedad y colaboración

Los repositorios pueden pertenecer a un usuario o a una organización. Además, pueden compartirse con otros colaboradores para trabajar de forma conjunta en el desarrollo y mantenimiento de un proyecto.

## Beneficios de Git y GitHub

- Control de versiones.
- Trabajo colaborativo.
- Historial de cambios.
- Recuperación de versiones anteriores.
- Gestión de ramas.
- Integración con herramientas DevOps.
- Automatización mediante GitHub Actions.

## Conclusión

Git y GitHub son herramientas fundamentales en el desarrollo moderno de software. Mientras que Git permite controlar y registrar los cambios realizados en un proyecto, GitHub facilita la colaboración, el almacenamiento y la administración del código. Su uso permite mantener proyectos organizados, mejorar el trabajo en equipo y aplicar buenas prácticas dentro de metodologías DevOps.
